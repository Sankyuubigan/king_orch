# План: голосовое общение с LLM (Voice Interface)

> Статус: **ПЛАН НА БУДУЩЕЕ**. Фаза 0 (гейтинг аудио-вложений) уже реализована —
> см. `src/controllers/chat.ts` (`updateAttachButtonState` / `handleFileSelect`) и
> команду `get_model_capabilities` в `src-tauri/src/api/models.rs`.
> Ниже — архитектура полноценного голосового режима (barge-in), пока НЕ реализовано.

## 1. Ключевой вывод про barge-in

Barge-in (прерывание речи ассистента) — это **не свойство модели**, а свойство
транспортного/оркестрационного слоя: микрофон + VAD + отмена TTS при перебивке.
Поэтому модели вроде **Ultravox** (аудио-НА-входе → текст-НА-выходе, без TTS и
без прерываний) его не дают. Нужно строить голосовой пайплайн вокруг существующего
текстового чата.

## 2. Референсные репозитории (barge-in есть)

- **Pipecat** (`pipecat-ai/pipecat`, ~14k★) — Python-фреймворк реального времени:
  STT/LLM/TTS подключаются по отдельности, Silero VAD, interrupt handling,
  транспорты WebRTC/WS. Ultravox у них — один из s2s-провайдеров.
- **LiveKit Agents** (`livekit/agents`, ~13k★) — Python, явная «Semantic turn
  detection» (transformer-VAD), режущая interruptions, встроенный VAD,
  STT/LLM/TTS pluggable. Есть **AgentsJS** (TS) для клиента.
- **OpenAI Realtime / Agents SDK** — референс по server-side VAD barge-in.
- Локально в браузере: `@ricky0123/vad-web` (Silero VAD в WASM), `whisper.cpp`
  (локальный STT), `Kokoro` / `Piper` (локальный TTS).

## 3. Принятые решения (по итогам обсуждения)

- **Считать звук во фронтенде** (WASM в браузере Tauri), не в Rust-бэкенде.
  Переиспользует TS-стек, не лезет в llama.cpp-инфру.
- **STT/TTS — локальные** (Whisper / Kokoro в WASM), для офлайн-десктопа.
- Голос = **I/O-адаптер вокруг существующего текстового чата**. LLM/агенты/
  оркестратор/история сообщений не меняются (AGENTS.md: единый источник правды —
  `messages[]`).

## 4. Архитектура

```
микрофон ──VAD(Silero WASM)──> STT(Whisper WASM) ──текст──> [chat_request + Гемма + агенты]
                                                                     │
ассистент <──TTS(Kokoro/Piper)──< текст ответа <─────────────────────┘
   ▲ barge-in: пока играет TTS, VAD слушает микрофон → перебил →
     стоп TTS + отмена генерации (cancel_flag, уже есть в коде)
```

Гемма **никогда не видит аудио** — только расшифрованный текст. Это снимает
проблему «Gemma не ест звук» (см. Фазу 0).

## 5. Точки интеграции в GUI

- Новый `VoiceController` (общение через шину, как велит AGENTS.md).
- Кнопка микрофона рядом с `btnSend` (`src/controllers/chat.ts`).
- Распознанный текст идёт через существующий `handleSend` → `chat_request`
  (переиспользуем рендер, сабчаты, историю).
- TTS-воспроизведение — отдельный плеер; barge-in отменяет текущий
  `cancel_flag` генерации и ставит TTS на паузу.

## 6. Режимы общения пользователя

1. **Push-to-talk** (Фаза 1, быстро): зажал микрофон → запись → отпускание →
   STT → обычное сообщение юзера (транскрипт виден в чате).
2. **Hands-free + barge-in** (Фаза 2): переключил «голосовой режим» → слушаем
   непрерывно, речь авто-отправляется, ответы озвучиваются; если юзер заговорил
   поверх ответа — barge-in режет TTS и прерывает генерацию.

## 7. Фазы

- **Фаза 0 (СДЕЛАНО):** гейтинг аудио-вложений по `audio`-флагу каталога
  (`get_model_capabilities`), правка `models_catalog.json` (Gemma `audio:true`→`false`),
  уборка `test/`.
- **Фаза 1:** Voice mode toggle + push-to-talk (STT → chat_request → TTS).
- **Фаза 2:** barge-in через Silero VAD (остановка TTS + отмена генерации при перебивке).
