## 1. Ключевой вывод про barge-in

Barge-in (прерывание речи ассистента) — это **не свойство модели**, а свойство
транспортного/оркестрационного слоя: микрофон + VAD + отмена TTS при перебивке.
Поэтому модели вроде **Ultravox** (аудио-НА-входе → текст-НА-выходе, без TTS и
без прерываний) его не дают. Нужно строить голосовой пайплайн вокруг существующего
текстового чата.

## 6. Режимы общения пользователя

1. **Push-to-talk** (Фаза 1, быстро): зажал микрофон → запись → отпускание →
   STT → обычное сообщение юзера (транскрипт виден в чате).
2. **Hands-free + barge-in** (Фаза 2): переключил «голосовой режим» → слушаем
   непрерывно, речь авто-отправляется, ответы озвучиваются; если юзер заговорил
   поверх ответа — barge-in режет TTS и прерывает генерацию.

### Почему для этих TTS нет Rust-крейтов? (Техническая причина)

Модели из твоего списка (1, 2, 4, 5, 6) — это **не классические TTS**. Это LLM-модели (архитектуры типа Qwen/Llama), которые научили генерировать аудио-токены.
Их инференс состоит из трех тяжелых шагов:
1. **LLM Forward Pass:** генерация невидимых токенов (Flow Matching / DiT архитектуры).
2. **Vocoder / Codebook Decoder:** перевод этих токенов в спектрограмму (например, через WavTokenizer).
3. **Vocoder to PCM:** перевод спектрограммы в звук.

В Rust есть движки для LLM (например, `llama.cpp` через `llama-cpp-sys-2`), но в `llama.cpp` **не реализованы** кастомные слои для декодирования аудио CosyVoice/Higgs. А Rust ML-фреймворки (`candle` от HuggingFace) не поддерживают эти специфические операции (Flow Matching) из коробки. Написать это с нуля на Rust — это месяцы работы команды программистов.

### Есть ли готовые C++ или Rust решения для запуска без Python?
Для CosyVoice и Higgs — **НЕТ**. Все репозитории на GitHub (`cosyvoice`, `higgs-audio`) жестко завязаны на PyTorch и `transformers`.

### Тот ли архитектурный план я предложил?

**Нет, мой прошлый план с "нативным ort + Piper" был устаревшим для тебя**, так как тебе нужно SOTA-качество и клонирование голоса, которое дают LLM-TTS.

Если мы хотим запустить CosyVoice 3 / Higgs внутри Tauri-приложения, есть **только один архитектурно правильный способ**, который не заставит пользователя устанавливать Python.

#### Архитектура: "Скомпилированный Portable Sidecar"

Мы не пишем инференс на Rust. Мы берем Python-код CosyVoice и компилируем его в один бинарник, который Tauri будет запускать как фоновый процесс.

**Как это реализуется технически (План):**

1. **Сборка Engine (на стороне разработчика - тебя):**
   * Берешь репозиторий `CosyVoice` или `Higgs-Audio`.
   * Оборачиваешь его в локальный HTTP-сервер на FastAPI/Uvicorn (или gRPC).
   * Компилируешь это в standalone `.exe` с помощью **Nuitka** (он компилирует Python в C-код) или **PyInstaller**. В этот `.exe` зашиваются веса модели (весит это будет 2-4 ГБ).
   * *Результат:* У тебя на выходе получается `cosyvoice_engine.exe`, который не требует установки Python на компьютер юзера.

2. **Интеграция в Rust + Tauri (Бэкенд):**
   В Tauri ты не лезешь в инференс. Ты пишешь менеджер процессов (по твоему правилу 6.7 из гайдлайна).
   * При старте приложения Rust запускает `cosyvoice_engine.exe` на скрытом порту (например, 4567).
   * Rust ждет ответа от `http://localhost:4567/health`.
   * Когда юзер жмет кнопку "Озвучить", Frontend вызывает Tauri-команду.
   * Rust отправляет `POST http://localhost:4567/tts` с текстом и референсом голоса.
   * Python-бинарь грузит GPU (CUDA/CPU) и возвращает WAV-аудио потоком (или чанками).
   * Rust прокидывает аудио в Frontend.

3. **Управление памятью (Правило 6.5):**
   Если у тебя в приложении уже крутится `llama-server.exe` (LLM), то запуск TTS-движка сожрет VRAM. 
   *Решение:* LLM генерирует текст -> выгружается из VRAM (`Drop` процесса) -> запускается TTS движок -> генерирует аудио -> выгружается -> LLM стартует снова. (Это медленно, но это единственный путь, если у юзера 6-8 ГБ видеопамяти. Если у юзера 12+ ГБ, могут работать параллельно).

### Альтернатива: Есть ли что-то современнее на чистом Rust?
Если ты не хочешь тащить гигабайтный Python-бинарь, есть компромисс — **Kokoro TTS**.
* Это не LLM, но это SOTA-модель на базе StyleTTS2 (размер всего 82 МБ).
* Она звучит в 10 раз лучше, чем Piper/Silero, почти как живой человек, поддерживает клонирование голоса.
* И самое главное: для нее **уже есть Rust-библиотека** (крейт `kokoro-tts-rs` или запуск через `ort`). Она запускается нативно внутри Rust/Tauri за 0.1 секунды на CPU и не требует Python.

### Итог: что выбирать?
1. **Если нужны CosyVoice/Higgs/Fish (SOTA LLM):** Готового крейта нет. Пишем FastAPI-сервер, компилируем через Nuitka в `.exe`, запускаем из Tauri как sidecar-процесс по HTTP.
2. **Если хочешь нативный Rust без Python:** Берем `kokoro-tts-rs` (82 МБ, работает мгновенно на CPU, качество на уровне старых добрых нейросетей Яндекса, но без эмоций LLM).
